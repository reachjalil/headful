# Admin Utilities beta

Use Admin Utilities to inspect records, run read-only queries, explore fields, check org health and open Salesforce Setup shortcuts. The deliberately public mod is included in Headful. Its five tools are available directly in each enabled org workspace. Salesforce permissions still apply; these tools cannot change records or approve writes.

## Current composition and targeting

Normal startup is Welcome → Salesforce CLI readiness → org connections → admin workspace. Choose Objects & fields, Query data, Inspect record, Org health or Setup shortcuts from the compact tool navigation. Both Setup entry points use the shared connection component. Settings → This Mac → Local mods exposes artifact inspection, permission review, lifecycle and declared mod commands/views. The earlier sidebar, search, notification inbox and customizable workspace header are superseded.

The workspace uses docked panels in an editor frame: a compact top bar for org switching and Salesforce, a horizontal tool strip, Workspace breadcrumbs and a slim connection status bar. Query data keeps Run query, starters, rows per page, Save and View together above the editor. Results occupy the remaining area and scroll independently. View opens the Fields, Saved queries or Query history reference panel; it can be hidden without losing drafts. Drag panel dividers to resize the object browser, field properties, query editor/results, reference or document source. Pointer updates run at most once per animation frame. Escape cancels the current resize and restores its starting size. With a divider focused, arrow keys adjust its width or height; Shift moves in larger steps, Home/End selects the limits and double-click restores its default. Query **View → Reset panel layout** restores the editor/reference sizes, reference position and tab order. On narrow windows the reference and properties dock below the working pane. An **Editor changed** label distinguishes retained results from edited query text; Executed query reveals the exact query that produced them. Settings remains a full page with grouped navigation.

Workspace tools, query reference panels and document views use draggable tabs with a visible insertion marker. Moving tabs preserves mounted content and does not activate a tool or execute a read. Arrow keys and Home/End move tab focus; Enter or Space selects it. Alt+Left/Right reorders the focused tab, Alt+Home restores its order, and right-click or Shift+F10 opens tab options. Opened declarative mod destinations join the workspace tab strip.

Drag a Fields, Saved or History tab into the query canvas to reveal left, right and below drop targets. The reference group moves together and the dropped tab becomes active. **View → Dock reference** provides the same positions without dragging. Drag a document Source or Preview tab to an edge to open a split with that pane on that side; **Layout → Source first / Preview first** provides keyboard-accessible placement. Document **Reset split layout** restores a balanced split and default tab order. Cancelling a document drag restores the starting view. Source editors and rendered documents stay mounted during these changes. Narrow windows stack query reference and document panes vertically with horizontal height dividers. Layout and tab order are local to the mounted org workspace; drafts remain pinned to their exact org.

Each workspace keeps its org and signed-in username visible. Switching tools preserves the current query draft; switching between opened orgs preserves their separate drafts. Successful connection rechecks keep that work mounted. A failed discovery or disabled connection removes unavailable workspaces. Each service operation names an imported org, resolves its verified identity/principal and enforces current feature, client, org and mod authority. Changing the default never retargets saved work.

Press **⌘K** (Ctrl+K on other keyboards) or open **Tools** to find an admin tool, a local mod tool or an action available in the current tool. Search by its name or supplying mod; arrow keys select a result, Enter opens it and Escape closes the menu. Unavailable items explain why. Workspace **Back** and **Forward** return to opened tools with their drafts and loaded results preserved. Choosing a new destination after going back starts a new path; navigation does not rerun a query or record read.

## Everyday utilities

- **Org shortcuts** opens the selected org or supported Salesforce Setup destinations. Favorites stay with that org. These are fixed destinations, not arbitrary URLs or CLI commands.
- **Record inspector** reads a record by object API name and Salesforce ID. Query results with an Id and a simple object selection offer direct access to this inspector with the exact object and record ID filled in. Choose **Inspect record** to read it. Filter field labels, API names, types, and values; copy individual values, the ID, or structured JSON; open the same record in its original org. Salesforce field permissions still apply.
- **SOQL workspace** runs one read-only `SELECT` query. Start with active users, permission sets or accounts, or write a query directly. Choosing a starter replaces the editor and runs only when you choose **Run query**. Object and field suggestions come from CLI schema reads. Queries and history are saved per org; history records query text and execution metadata, without retaining result datasets. Results load in pages of at most 500 rows, with a one-row look-ahead and a 2,000-row offset bound. **Cancel query** terminates the owned CLI child. **Export this page CSV** exports only loaded rows and does not fetch additional pages.
- **Object & field explorer** browses object API names and describes accessible fields, types, picklists, and relationships. Search field labels/API names, select fields, then choose **Query selected** to open the SOQL editor. The query runs only when you choose **Run query**. Select a field to inspect its **Properties** beside the table; Field details, Formula source and Picklist values are collapsible groups. You can also export local schema documentation. The explorer creates or deletes no schema.
- **Org diagnostics** reads supported limits and storage, recent Apex jobs, and available debug logs. Choose Storage & limits, Jobs or Debug logs in the panel header. Opening Debug logs does not fetch logs; choose **List available logs** and then **Read log** explicitly. Missing CLI capabilities and Salesforce permissions produce useful unavailable states. It performs no job execution or log configuration.

Copied values and exported files are local CRM data. You decide where to share them. Using an external agent provider separately can send selected CRM context to that provider.

## CLI and authority boundary

The command families were checked against Salesforce CLI **2.136.0+**: `data query`, `data get record`, `sobject list`, `sobject describe`, `org list limits`, `apex list log`, `apex get log`, and `org open`. The fixed identity check uses CLI-owned `org display` and `api request rest /services/oauth2/userinfo --method GET`; that installed API command prints JSON directly and does not support a `--json` flag.

The runtime validates explicit target usernames, authenticated org/principal/origin, inputs, JSON output shapes, execution time and output size. It executes argument arrays without a shell. Mod permissions grant narrow reads, never an unrestricted CLI capability, Apex execution, credentials, or write approval. Disabled services reject late results; disabling query access aborts active reads. There is no credential-based REST fallback for these utilities.

Users & Access and Permission Sets retain their existing exact human review, expiring single-use approvals, stale-state validation, provider receipts, and unknown-outcome reconciliation. Utility reads cannot bypass those safeguards.

## Scope and distribution

A clean public clone runs `pnpm headful:setup`, `pnpm headful:dev`, and `pnpm headful:package` without a private repository or npm credentials. The proprietary `@headfulcloud/mcp-apps` integration is a separately assembled optional compiled mod; see [Mods](MODS.md).

This is a Mac beta, initially packaged on Apple Silicon. Mobile source and shared T3 client architecture are preserved; mobile development and distribution are outside this slice. Backups and restore are planned for a separate proprietary Mod. Scheduled snapshots, sandbox seeding, metadata deployment/comparison, bulk imports, and advanced automation are also outside this beta. The utilities do not claim full Salesforce Inspector, ORGanizer, or DevTools parity.
