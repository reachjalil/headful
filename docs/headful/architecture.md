# Headful adaptation boundaries

Headful retains the T3 Code application and server rather than wrapping a separate scaffold. The existing desktop lifecycle starts one backend and stops it on Quit. A scoped Headful Effect service in that backend owns the local Salesforce store, CLI adapter, org context, reviewed workflows and the extension host. Desktop and contributed MCP transports call that same service. Desktop IPC validates the installed application sender; its authorization is an exact-body signature from a capability held in native memory, never in a file or renderer code. The backend removes that capability from its environment before starting Salesforce CLI or provider subprocesses. MCP clients receive their own revocable, org-scoped grants. Neither an extension nor a model call can approve a provider write.

The public Salesforce workspace renderer, pure contracts, bounded REST operations, and exact reviewed user/access/permission workflows were deliberately adapted from the author's existing Headful Cloud implementation. Cloud-specific account sessions, OAuth applications, vault keys, production configuration and private coordination material were not transferred. Temporary public/local and private/cloud persistence adapters share the same originating workflow algorithm; consolidation should extract pure operation decisions without coupling portable contracts to either runtime.

Salesforce CLI retains Salesforce authentication and refresh tokens. Headful calls approved CLI commands with validated argument arrays and short-lived provider access remains server-side. Ordinary metadata and durable workflows live in an owner-only SQLite store. Headful client grants are hashed in an owner-only grant store; separately generated owner-only bridge credential files contain only Headful grants. They can be revoked without changing Salesforce authentication.

Feature registry decisions apply in service dispatch and MCP discovery as well as navigation. Disabling an org or feature blocks new operations. An in-flight provider write cannot honestly be described as cancelled; its durable receipt or unknown outcome remains available for review.

The packaged application includes local resource HTML/CSS/JavaScript and its stdio helper. No desktop product asset or Salesforce request depends on Headful Cloud. Generic MCP clients get structured and text results. Host rendering and fullscreen capabilities are feature detected; native-host acceptance is separate from protocol and fixture checks.

`apps/mobile` and shared T3 client foundations remain intact. Initial development and packaging are Mac-only, and there is no mobile distribution or unauthenticated remote Salesforce endpoint in this release.
